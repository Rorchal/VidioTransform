# 设计笔记：依赖图上下文压缩

## 一句话

**一段内容离当前目标越远，就用越低的分辨率保存它。** 距离决定分辨率，分辨率决定 token 开销。
和 GC 的关系：保留"从根追踪"，但把"可达 / 不可达"改成"距离分级"，把"删除"改成"换出 + 存根"，再加一层"状态 vs 历史"处理覆盖关系。

## 和垃圾回收的不同点（为什么不能照搬）

| | GC | 上下文压缩 |
|---|---|---|
| 边 | 指针，精确、免费 | 要推断，模糊，有置信度；mark 阶段是成本中心 |
| 可达性 | 二值 | 连续；动作也分 4 档（原文 / 摘要 / 一行 / 存根） |
| 根 | 运行时给定（栈、全局变量） | 当前目标 + 硬约束，要推断且会漂移 |
| 死亡 | 永久 | 会复活（"回到刚才那个方案"）→ 不能 free，只能换出 |
| 活对象的代价 | 无 | 有：太长模型也会变差，活的也要压 |
| 错误代价 | 误删 = 崩溃，必须保守 | 误删 = 效果下降；可以更激进，但只有质量评估没有正确性证明 |
| 对象边界 | allocator 给定 | 要自己切；一条消息里可能一半重要一半没用 |
| 覆盖关系 | 无对应物 | 先说 A 后改 B：A 可达但已失效 → 版本问题 |

## 借鉴的领域

- **编译器**：程序切片（从 criterion 后向找依赖）、死存储消除（被覆盖的旧值）、**栈帧弹出**（子任务结束，局部变量死、返回值活）。
- **操作系统**：缓存换出 + 后备存储；存根 = 页表项，"缺页"= 模型要求取回。
- **事件溯源 / Kafka 日志压缩 / ADR**：状态 vs 历史；每个 key 只留最新值；**墓碑**标记被删除/被否决的东西，防止重新提出。
- **图形学 LOD / mipmap**：每个块预生成多个分辨率，按距离选；按预算分配而不是写死阈值。
- **构建系统**：摘要缓存，子树不变不重算；失效传播。
- **信息论 / 图式理论**：可预测的删、意外的留；评估用任务效果（率失真），不用文本相似度。
- **人类交接文档**：固定槽位（目标、约束、决策含否决项、当前状态、未决问题）比自由摘要可靠。

## 机制

1. **图**：节点 = 块；边 src→dst = "src 重要则 dst 也重要 × 强度"（等价于 src 依赖 dst）；根 = 目标与硬约束，强度 1.0。
2. **距离**：从根出发，路径强度 = 边强度连乘，节点强度 = 所有路径取最大（Dijkstra，−log s 空间相加等价于 s 空间相乘）。走不到 = 0。
3. **分辨率**：L0 原文 / L1 段落摘要 / L2 一句话 / L3 存根（只有 id + 几个词，原文在冷存储）。
4. **分配**：全部从 L3 起步，目标与约束钉在 L0；按 `强度 × 增益 / token 增量` 贪心升档；升档时把强依赖拉到不低于自己一档（结论原文不能指向被换出的前提）；可达节点先分完，剩余预算才给不可达节点；被取代 / 被否决的节点固定为墓碑。
5. **帧**：用户每次发言开新帧，助手给出 Decision 关掉当前帧；已关闭帧的内部（工具调用、结果、过程性文字）强度减半，结论保留。

## 块的粒度

| 层 | 是什么 | 怎么得到 |
|---|---|---|
| 帧 | 一个子任务 | 用户发言 / Decision 标记 |
| 步骤 | 一次调工具 + 看结果 | API 格式 |
| 消息 | 一条用户 / 助手 / 工具调用 / 工具结果 | API 格式（底层单位） |
| 事实 | 一条用户消息里的一句话 | 句子切分；约束藏在长消息里时必须拆 |

步骤顺序不是边。第 5 步可能依赖第 1 步而不依赖第 4 步。

## 边的来源

| 来源 | 成本 | 准确度 | 强度 |
|---|---|---|---|
| 结构边：调用↔结果、助手文字→刚读的结果、助手文字→上一条助手文字（链）、用户请求→回复 | 免费 | 精确 | 1.0 / 1.0 / 0.5 / 0.4–0.9 |
| 符号边：共享标识符（文件名、函数名、常量、带单位的数、报错码） | 免费 | 中 | 0.5 / 0.3 |
| 启发式：赋值取代（`set KEY to X`）、否决（否定词 + 与提案共词） | 免费 | 中低 | 墓碑 |
| 模型推断（`llm.py`）：每个文本块一次调用，输入 = 新块 + 索引（已有节点各一行）；工具调用 / 结果不送模型（结构边已给） | 贵，O(n) | 高（DeepSeek V4.1-Flash：P 0.41 / R 0.77，墓碑归因 100%） | 类型查表 × 置信度；`supports` 反向成 目标→块 |

模型只在两处被调用：建边一次、生成 L1/L2 一次（结果缓存）。其余全是确定性代码。

## 评测方法（evalkit/）

- 合成 agent 对话：目标 + 约束、带噪声的工具输出、决策、被否决的提案、被更新的配置值、无关闲聊、修复、测试。
- 真值：角色、边、取代、否决；问题按失败模式分类（近根 / 深层 / 更新 / 否决 / 约束 / 闲聊 / 指令）。
- 指标：同预算下的答案保留率、可取回率（答案在 或 指向它的存根在）、**旧值仍被当作有效内容呈现**、实际用量、边的精确率/召回率。
- 基线：全量、截断、随机、均匀降档、二值 GC。消融：去句子拆分 / 去墓碑 / 去帧 / 去级联 / 去符号边 / 换真边。
- 参考答案不需要人标：用全量上下文的答案做参考即可衡量压缩损失。
