# ctxgc — 依赖图上下文压缩

借垃圾回收的"从根追踪"思路做 LLM 上下文压缩，但做了三处关键改动：
**可达 / 不可达 → 距离分级（L0 原文 / L1 摘要 / L2 一句话 / L3 存根）**，
**删除 → 换出 + 存根（永不删除，可取回）**，
**加一层"状态 vs 历史"（被取代 / 被否决的内容变墓碑）**。
设计推导见 [docs/design-notes.md](docs/design-notes.md)。

## 目录

```
src/ctxgc/
  model.py       节点 / 边 / 图；边 src→dst = "src 重要则 dst 也重要 × 强度"
  ingest.py      transcript → 节点 + 结构边（调用↔结果、读取、链、请求→回复）；用户消息拆到句子级事实
  edges.py       免模型的边：共享标识符、赋值取代、提案否决
  propagate.py   从根传播强度（路径连乘、多路径取最大）；帧弹出；近因下限
  summarize.py   每个节点的 4 档版本（抽取式；可换成 LLM）
  allocate.py    按预算分配档位：密度贪心 + 级联拉前提 + 可达优先 + 墓碑固定
  render.py      输出；连续存根折叠成一行
  compress.py    流水线入口 + 基线（full / truncate / random / uniform / gc_binary）
  llm.py         模型做的两步：建边（每个文本块一次调用）和 L1/L2 摘要；DeepSeek / Anthropic 后端，回复缓存成 JSONL
evalkit/
  synth.py       合成 agent 对话 + 真值（角色、边、取代、否决、问答）
  metrics.py     答案保留、可取回、旧值曝光、边的 P/R
  run.py         跑评测，输出 evalkit/results/summary.md；--llm 加上模型建边 / 模型摘要四种方法
tests/           19 个单元/端到端测试（模型相关的用假模型跑，不联网）
```

## 运行

```bash
pip install pytest
python -m pytest -q                              # 19 passed
python -m evalkit.run --cases 30                 # ~10s，结果在 evalkit/results/
python -m evalkit.run --cases 30 --llm deepseek  # 加上模型建边 / 模型摘要；需要 DEEPSEEK_API_KEY
```

模型回复缓存在 `evalkit/results/llm_cache.jsonl`（已提交），所以第二条命令在没有凭证的机器上也能原样复现下面的数字（全部命中缓存，0 次调用，约 20s）。改了提示词才会重新调用。

## 结果（30 个合成对话）

预算 = 全量上下文 token 数的比例；数字 = 答案字符串仍在压缩后上下文里的比例。完整表格见 [evalkit/results/summary.md](evalkit/results/summary.md)。模型 = DeepSeek V4.1-Flash（建边开低档思考，摘要关思考）。

| 方法 | 答案保留 @20% | @35% | @60% | 旧值仍被当作有效 @20%（越低越好） | 可取回 @10% |
|---|---|---|---|---|---|
| full（不压缩） | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| truncate（留最近） | 0.61 | 0.86 | 0.90 | 0.97 | 0.43 |
| random | 0.79 | 0.87 | 0.85 | 0.84 | 0.62 |
| uniform（全部同档） | 0.57 | 0.85 | 0.88 | 0.77 | 0.87 |
| gc_binary（可达留 / 不可达删） | 0.61 | 0.86 | 0.90 | 0.97 | 0.43 |
| **graded（本方法，启发式边 + 抽取式摘要）** | **0.80** | **0.98** | **0.98** | **0.00** | **1.00** |
| graded + 真边 | 0.79 | 0.98 | 0.98 | 0.00 | 1.00 |
| graded + 模型建边 | 0.79 | 0.98 | 0.98 | 0.00 | 1.00 |
| graded + 模型摘要 | 0.84 | 1.00 | 1.00 | 0.00 | 1.00 |
| **graded + 模型建边 + 模型摘要** | **0.86** | **1.00** | **1.00** | **0.00** | **1.00** |

按问题类型 @20%：graded 在 近根 0.97 / 约束 1.00 / 否决 1.00 / 更新 1.00 / 指令 1.00；深层事实 0.03（35% 时 0.88）。截断对应为 0.69 / 0.00 / 0.47 / 1.00 / 1.00 / 0.50。模型建边 + 模型摘要把深层事实提到 0.28（35% 时 1.00），其余类型全 1.00。

**建边阶段（mark）对比真边**，30 例平均：

| 边的来源 | 精确率 | 召回率 | 每例预测边数（真边 24） | 旧值归因到确切更新句 | 否决检出（精确归因） | 用户句子角色准确率 |
|---|---|---|---|---|---|---|
| 免模型启发式（结构 + 符号 + 正则） | 0.10 | 0.53 | 128 | 0.37 | 0.63 | 0.57（闲聊 0%） |
| DeepSeek V4.1-Flash，每块一次调用 | 0.41 | 0.77 | 46 | 1.00 | 1.00 | 0.83（闲聊 100%） |

误报的墓碑两边都是 0。

## 主要发现

1. **20% 预算以上，分级 + 换出明显优于截断、均匀降档和二值 GC**；35% 时 0.98 对 0.86。二值 GC 和截断表现一样——可达性本身不是瓶颈，分辨率分级才是。
2. **墓碑是最干净的收益。** 旧值被当作有效内容呈现：graded 0%，其他方法 77–100%，全量上下文本身也是 100%（它把判断"哪个值是现在的"推给模型）。
3. **10% 是这套设计的下限。** 钉住的根 2% + 墓碑 1% + 折叠后的存根 7% ≈ 10.4%，没有余量升档。要支持更低预算需要帧级存根（一个已关闭子任务一个存根）。
4. **消融几乎无差别**（符号边 / 级联 / 句子拆分 / 真边 vs 启发式边）。这说明合成数据还不够刁钻：约束都在短消息里（拆句的价值体现不出来），深层事实靠摘要器的"任务相关行优先"就能捞到。下一步要加的难度：长消息里埋约束、多跳推理、同一标识符在无关处大量出现。
5. **免模型建边的缺口**：精确率 0.10（过度连边，128 条 vs 真边 24 条）、召回 0.53；旧值墓碑 100%（但归因到确切的更新句只有 37%，常是助手的确认句触发的）；否决检出 63%；用户句子角色准确率 57%，**完全分不出闲聊和指令**。
6. **模型建边把这个缺口补上了大半**：精确率 0.41 / 召回 0.77，墓碑归因 100% / 100%，闲聊 100% 识别。剩下的误报多是"每句助手叙述都 supports 目标"（真边表里没有这类边，但传播上无害）；剩下的漏报主要是"fix 决策 → 目标"这条边被每块 4 条的上限挤掉（30 例漏 24 次）。角色错误里 30/30 是把收尾的 "Great." 标成 user——真值把它标成 goal，模型其实更对。
7. **边不是瓶颈，摘要是。** 模型建边单独上场，答案保留和启发式一样（0.79 对 0.80 @20%）——和"真边 vs 启发式边几乎无差别"的消融一致。换成模型摘要，20% 时 0.80→0.84，加上模型建边 0.86，35% 起全部 1.00；深层事实 @20% 从 0.03 到 0.28。模型摘要的好处是任务相关：给它开头那轮用户消息当上下文，它从 140 行日志里挑出带 TODO 注释、延迟数字的那几行。
8. 两个会让数字偏乐观的地方：(a) 深层事实依赖抽取式摘要器按"对话里提过的标识符"挑行，所有方法共用；(b) 存根的 3 词预览有时直接带出答案（闲聊里的颜色），chatter 列因此接近满分。一个让模型摘要偏悲观的地方：指标是字符串匹配，"TODO to batch the queries" 对不上 "TODO batch this"，算丢。

## 限制

- 模型只跑了 DeepSeek V4.1-Flash（30 例：建边 615 次调用 / 61 万输入 token，摘要 1167 次 / 50 万；16 线程 8 分钟）。Anthropic 后端写好了没跑。建边提示词不是在真值上调出来的，只按设计笔记里的边语义写。
- 本轮修了一个存根 bug：节点很短时 L3 存根比 L2 还长，旧代码会把存根换成 L2 文本，存根就丢了 id、也不能折叠。修完 uniform 基线在 10%–20% 掉了几个点（它之前靠"存根其实是整句"占了便宜），其他方法没动。
- token 数是 chars/4 的近似，只用于方法间同预算比较。
- 单次快照，没测多轮之间的稳定性（滞后阈值未实现）。
- 评测衡量的是"答案还在不在上下文里"，不是模型答对与否；接 API 后用全量上下文的答案做参考即可升级。
