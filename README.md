# ctxgc — 依赖图上下文压缩

借垃圾回收的"从根追踪"思路做 LLM 上下文压缩，但做了三处关键改动：
**可达 / 不可达 → 距离分级（L0 原文 / L1 摘要 / L2 一句话 / L3 存根）**，
**删除 → 换出 + 存根（永不删除，可取回）**，
**加一层"状态 vs 历史"（被取代 / 被否决的内容变墓碑）**。
设计推导见 [docs/design-notes.md](docs/design-notes.md)。

## 目录

```
src/ctxgc/
  model.py       节点 / 边 / 图；边 src→dst = "src 重要则 dst 也重要 × 强度"
  ingest.py      transcript → 节点 + 结构边（调用↔结果、读取、链、请求→回复）；用户消息拆到句子级事实
  edges.py       免模型的边：共享标识符、赋值取代、提案否决
  propagate.py   从根传播强度（路径连乘、多路径取最大）；帧弹出；近因下限
  summarize.py   每个节点的 4 档版本（抽取式；可换成 LLM）
  allocate.py    按预算分配档位：密度贪心 + 级联拉前提 + 可达优先 + 墓碑固定
  render.py      输出；连续存根折叠成一行
  compress.py    流水线入口 + 基线（full / truncate / random / uniform / gc_binary）
  llm.py         模型做的两步：建边（每个文本块一次调用）和 L1/L2 摘要；DeepSeek / Anthropic 后端，回复缓存成 JSONL
evalkit/
  synth.py       合成 agent 对话 + 真值（角色、边、取代、否决、问答）
  metrics.py     答案保留、可取回、旧值曝光、边的 P/R
  run.py         跑评测，输出 evalkit/results/summary.md；--llm 加上模型建边 / 模型摘要四种方法
  real.py        真实 agent 轨迹上的免标注评测：SWE-agent 轨迹 / Claude Code 会话日志 → 切点 → "后面用到的标识符还在不在"
tests/           27 个单元/端到端测试（模型相关的用假模型跑，不联网）
```

## 运行

```bash
pip install pytest
python -m pytest -q                              # 19 passed
python -m evalkit.run --cases 30                 # ~10s，结果在 evalkit/results/
python -m evalkit.run --cases 30 --llm deepseek  # 加上模型建边 / 模型摘要；需要 DEEPSEEK_API_KEY

# 真实轨迹：Nebius 公开的 SWE-agent 轨迹（任取一个 parquet 分片，约 90MB）+ 自己的 Claude Code 会话日志
pip install pyarrow
curl -L -o shard.parquet https://huggingface.co/datasets/nebius/SWE-agent-trajectories/resolve/main/data/train-00006-of-00012.parquet
python -m evalkit.real --swe-agent shard.parquet --n 60 --skip 10 --claude-code ~/.claude/projects/<proj>/<session>.jsonl
```

模型回复缓存在 `evalkit/results/llm_cache.jsonl`（已提交），所以第二条命令在没有凭证的机器上也能原样复现下面的数字（全部命中缓存，0 次调用，约 20s）。改了提示词才会重新调用。

## 结果一：30 个合成对话

预算 = 全量上下文 token 数的比例；数字 = 答案字符串仍在压缩后上下文里的比例。完整表格见 [evalkit/results/summary.md](evalkit/results/summary.md)。模型 = DeepSeek V4.1-Flash（建边开低档思考，摘要关思考）。

| 方法 | 答案保留 @20% | @35% | @60% | 旧值仍被当作有效 @20%（越低越好） | 可取回 @10% |
|---|---|---|---|---|---|
| full（不压缩） | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| truncate（留最近） | 0.61 | 0.86 | 0.90 | 0.97 | 0.43 |
| random | 0.79 | 0.87 | 0.85 | 0.84 | 0.62 |
| uniform（全部同档） | 0.57 | 0.85 | 0.88 | 0.77 | 0.87 |
| gc_binary（可达留 / 不可达删） | 0.61 | 0.86 | 0.90 | 0.97 | 0.43 |
| **graded（本方法，启发式边 + 抽取式摘要）** | **0.81** | **0.98** | **0.98** | **0.00** | **1.00** |
| graded-agent（增益 = 新增标识符数，见结果二） | 0.70 | 0.95 | 0.98 | 0.00 | 1.00 |
| graded + 真边 | 0.79 | 0.98 | 0.98 | 0.00 | 1.00 |
| graded + 模型建边 | 0.78 | 0.98 | 0.98 | 0.00 | 1.00 |
| graded + 模型摘要 | 0.85 | 1.00 | 1.00 | 0.00 | 1.00 |
| **graded + 模型建边 + 模型摘要** | **0.84** | **1.00** | **1.00** | **0.00** | **1.00** |

按问题类型 @20%：graded 在 近根 1.00 / 约束 1.00 / 否决 1.00 / 更新 1.00 / 指令 1.00；深层事实 0.03（35% 时 0.88）。截断对应为 0.69 / 0.00 / 0.47 / 1.00 / 1.00 / 0.50。模型摘要把深层事实提到 0.28（35% 时 1.00）。

**建边阶段（mark）对比真边**，30 例平均：

| 边的来源 | 精确率 | 召回率 | 每例预测边数（真边 24） | 旧值归因到确切更新句 | 否决检出（精确归因） | 用户句子角色准确率 |
|---|---|---|---|---|---|---|
| 免模型启发式（结构 + 符号 + 正则） | 0.10 | 0.53 | 128 | 0.37 | 0.63 | 0.57（闲聊 0%） |
| DeepSeek V4.1-Flash，每块一次调用 | 0.41 | 0.77 | 46 | 1.00 | 1.00 | 0.83（闲聊 100%） |

误报的墓碑两边都是 0。

## 结果二：真实 agent 轨迹（免标注）

合成集只有一个骨架，说明不了真实表现，所以加了一套不需要标注的评测（`evalkit/real.py`）：把一条真实轨迹在中途切开，压缩前半段，看 **agent 后半段自己用到的标识符**（文件名、函数名、常量、带单位的数、报错码）里，有多少在前半段被工具输出发现过、而且还在压缩后的上下文里。agent 的"未来"就是它工作集的真值。另外三个量：**可取回**（在，或者持有它的节点的存根还在）、**不重读**（后面命令里点名的文件路径还在原文里，丢了就得重新 open）、**目标保留**（开头请求里的标识符，agent 后面还在用的）。

数据：Nebius 公开的 SWE-agent 轨迹（Llama 70B 跑 SWE-bench 类任务，一个 issue、十几步工具调用、前缀约 8k token），分配器设置在 10 条上选定、在另外 **60 条（90 个切点）** 上报告；加上本仓库这次开发的 Claude Code 会话（71k token 前缀、12 轮用户发言，只有 1 条，2 个切点）。

| SWE-agent 60 条 | 用到的标识符还在 @10% | @20% | @35% | @60% | 不重读 @10% | @20% | 目标保留 @10% | 可取回 @10% |
|---|---|---|---|---|---|---|---|---|
| truncate | **0.74** | **0.83** | **0.89** | **0.98** | 0.78 | 0.83 | 0.69 | 0.74 |
| random | 0.65 | 0.78 | 0.89 | 0.95 | 0.78 | 0.92 | 0.68 | 0.65 |
| graded（默认） | 0.22 | 0.45 | 0.72 | 0.84 | 0.34 | 0.72 | 0.20 | 1.00 |
| graded-agent | 0.53 | 0.72 | 0.79 | 0.88 | **0.89** | **0.90** | 0.50 | 1.00 |
| graded，开头整段钉原文（旧规则） | 0.09 | 0.24 | 0.58 | 0.83 | 0.07 | 0.33 | 0.97 | 1.00 |

| Claude Code 会话（n=1） | 用到的标识符还在 @10% | @20% | @35% | @60% | 不重读 @20% | 可取回 @20% |
|---|---|---|---|---|---|---|
| truncate | 0.25 | 0.38 | 0.48 | 0.68 | 0.54 | 0.38 |
| random | 0.33 | 0.45 | **0.62** | **0.83** | 0.79 | 0.65 |
| graded（默认） | 0.23 | 0.41 | 0.54 | 0.65 | 0.85 | 1.00 |
| graded-agent | 0.31 | **0.46** | 0.58 | 0.75 | **0.85** | 1.00 |

`graded-agent` = 分配器的升档增益改成"这一档比上一档多出几个标识符"（`gain="idents"`），其余同默认。

## 主要发现

1. **20% 预算以上，分级 + 换出明显优于截断、均匀降档和二值 GC**；35% 时 0.98 对 0.86。二值 GC 和截断表现一样——可达性本身不是瓶颈，分辨率分级才是。
2. **墓碑是最干净的收益。** 旧值被当作有效内容呈现：graded 0%，其他方法 77–100%，全量上下文本身也是 100%（它把判断"哪个值是现在的"推给模型）。
3. **存根的固定开销比想象的大。** 真实前缀 60 多个节点，带 3 词预览的存根组要 512 token，占 10% 预算的 78%。改成只留 id 和角色计数后 137 token。预览还曾在合成集上直接泄露答案（闲聊里的颜色），去掉后 chatter 列才是真实水平。
4. **开头请求不能整段钉死。** SWE-agent 的开头是 issue 全文加指令模板，约 1100 token，一个节点就超过 10% 预算。现在钉住只保证"占预算 30% 以内的最细档"，之后和别的节点一样竞争升档。这一条在合成集上没有体现，因为合成的目标只有三句话。
5. **免模型建边的缺口**：精确率 0.10（过度连边，128 条 vs 真边 24 条）、召回 0.53；旧值墓碑 100%（但归因到确切的更新句只有 37%，常是助手的确认句触发的）；否决检出 63%；用户句子角色准确率 57%，**完全分不出闲聊和指令**。
6. **模型建边把这个缺口补上了大半**：精确率 0.41 / 召回 0.77，墓碑归因 100% / 100%，闲聊 100% 识别。剩下的误报多是"每句助手叙述都 supports 目标"（真边表里没有这类边，但传播上无害）；剩下的漏报主要是"fix 决策 → 目标"这条边被每块 4 条的上限挤掉（30 例漏 24 次）。角色错误里 30/30 是把收尾的 "Great." 标成 user——真值把它标成 goal，模型其实更对。
7. **合成集上边不是瓶颈，摘要是。** 模型建边单独上场，答案保留和启发式一样（0.78 对 0.81 @20%）。换成模型摘要，20% 时 0.81→0.85，35% 起全部 1.00；深层事实 @20% 从 0.03 到 0.28。模型摘要的好处是任务相关：给它开头那轮用户消息当上下文，它从 140 行日志里挑出带 TODO 注释、延迟数字的那几行。
8. **真实 SWE-agent 轨迹上，截断是很强的基线，本方法目前没有超过它。** agent 下一步用到的东西 48% 就在上一步的工具输出里，只有 16% 在 4 步以前；而且 agent 要的是原文（函数名、行号），不是摘要。截断把全部预算花在最近的原文上，正中要害。graded 要给目标留预算、给每个节点留存根、给可达节点分摘要，这些在"下一步用什么"上都不计分。graded-agent 把差距从 0.45 缩到 0.72（@20%），在不重读（0.90 对 0.83）和可取回（1.00 对 0.83）上赢，在"用到的标识符还在"上仍输 5–20 个点。**random 也强**：标识符通常出现在多个节点里，随机留 60% 原文就能覆盖 95%——说明在这类数据上"整块原文 vs 什么都不留"好过"每块一个抽取式摘要"。
9. **轨迹越长、越多轮，本方法越占优。** 71k token、12 轮用户发言的 Claude Code 会话里，agent 后面用的东西 87% 在 4 步以前，截断在每个预算都最差，graded-agent 在 10–20% 最好、不重读 0.85 对 0.54。但只有 1 条，是线索不是结论。
10. **增益函数要和消费者匹配，而且 10 条轨迹不够选参数。** 标识符增益在合成集上丢闲聊和纯文字决策（0.81→0.70 @20%），在真实轨迹上大胜；它在 10 条选参轨迹上 @10% 是 0.64，换 60 条就是 0.53。所以它是显式配置，不是默认。
11. 几个会让数字偏乐观或偏悲观的地方：(a) 合成集的深层事实依赖抽取式摘要器按"对话里提过的标识符"挑行，所有方法共用；(b) 合成集指标是字符串匹配，"TODO to batch the queries" 对不上 "TODO batch this"，模型摘要被低估；(c) 真实轨迹指标数的是标识符，graded-agent 的增益也数标识符，两者耦合——"不重读"和 Claude Code 那条的提升不受这个影响，"用到的标识符还在"受。

## 限制

- 模型只跑了 DeepSeek V4.1-Flash（30 例：建边 615 次调用 / 61 万输入 token，摘要 1167 次 / 50 万；16 线程 8 分钟）。V4 Pro 建边跑了 10 例就停了（精确率 0.46 / 召回 0.68 / 角色 0.89，比 Flash 边更少更准），没跑完不进表。Anthropic 后端写好了没跑。建边提示词不是在真值上调出来的，只按设计笔记里的边语义写。
- 真实轨迹上**没有跑模型摘要**。发现 8 说抽取式摘要留不住 agent 要的原文，模型摘要能不能留住是下一步最值得花钱验证的事。
- 真实轨迹评测衡量的是"后面用到的东西还在不在"，没有把 agent 真的接上压缩后的上下文续跑。续跑才能测重复劳动、约束违反和任务成败，Nebius 数据带每条轨迹的通过/失败标签，可以做。
- token 数是 chars/4 的近似，只用于方法间同预算比较。
- 单次快照，没测多轮之间的稳定性（滞后阈值未实现）。
- 本轮修了一个存根 bug：节点很短时 L3 存根比 L2 还长，旧代码会把存根换成 L2 文本，存根就丢了 id、也不能折叠。修完 uniform 基线在 10%–20% 掉了几个点（它之前靠"存根其实是整句"占了便宜），其他方法没动。
